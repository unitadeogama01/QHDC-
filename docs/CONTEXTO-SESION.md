# Contexto de trabajo — Despensa Inteligente (QHDC!)

> Archivo para continuar el trabajo en otra computadora o en otra sesión de Claude Code.
> Al empezar una sesión nueva: leer este archivo y `docs/PLAN-IMPLEMENTACION.md`.

## Forma de trabajar (pedida por el usuario)
- Desarrollo **por fases**; al terminar cada fase se verifica y se **espera autorización** antes de la siguiente.
- **No rediseñar la interfaz**: conservar colores, tipografías, tarjetas, menús, iconos y estructura visual. Se puede reorganizar el código.
- No migrar a React u otro framework. No agregar tecnologías sin justificar qué problema resuelven.
- Todo el código, comentarios y textos en **español** (convenciones en `CLAUDE.md`).
- El **mismo código** debe correr en local y en Hostinger; solo cambia `backend/.env`.

## Decisiones tomadas
| Tema | Decisión |
|---|---|
| Arquitectura | Monolito modular (Express) + MySQL + MQTT para IoT + HTTP/multipart para fotos |
| Hostinger | Plan aún no decidido (VPS o compartido) → broker MQTT configurable por `.env`, Docker opcional |
| IA | Claude API desde el backend (`@anthropic-ai/sdk`, modelo `claude-opus-5-5`); sin `ANTHROPIC_API_KEY` se usa el reconocimiento simulado actual |
| Hardware real | 1 ESP32 DevKit + celda de carga (1–5 kg) con HX711 + DHT22, alimentado por USB. No hay cámara en el ESP32, ni sensor de gas, ni batería. **Al 2026-11-08 el usuario tiene el ESP32 y el celular; le falta el DHT22** (el firmware tiene `USAR_DHT22` / `USAR_BASCULA` en config.h para probar sin ellos) |
| Gas / batería / dispositivos extra en la UI | **Ocultarlos sin borrar código**: se muestran solo si un dispositivo reporta ese tipo de lectura |
| Fotos | Desde el teléfono (cámara o galería) o la PC, subidas por HTTP al backend; nunca por MQTT |

## Pendientes y avisos para la siguiente sesión
1. **Equipo de trabajo:** PC actual con Node v26.13.0 (en `%LOCALAPPDATA%\Programs\nodejs`, PATH de usuario), MySQL 8.0.46 (servicio MySQL80) y MySQL Workbench. La contraseña de root está en `backend/.env` (no se sube a Git).
   - Ojo al probar procedimientos: `sp_aplicar_lectura_peso`, `sp_consumir`, etc. abren su propia transacción, así que un `ROLLBACK` externo no deshace lo que hacen.
2. **Si se usa XAMPP, revisar el motor de base de datos.** XAMPP suele traer **MariaDB**, no MySQL 8. El script usa `COLLATE utf8mb4_0900_ai_ci` (exclusivo de MySQL 8 o de MariaDB reciente), `CHECK`, columnas generadas, JSON y procedimientos. Comprobar con `SELECT VERSION();`. Si es MariaDB y el script falla, decidir con el usuario: ajustar el script para que sea compatible con ambos (por ejemplo `utf8mb4_unicode_ci`) o instalar MySQL 8.
3. Comprobar que la app arranca igual que antes: en `backend/`, `npm install` y `npm start`, luego `http://localhost:3000` y `GET /api/salud`.
4. El `backend/.env` con contraseñas **no está en el repositorio**: en la otra PC hay que tener el suyo (basado en `.env.example`) con `SIMULADOR=true` para presentar sin hardware.
5. Requisito de Node: ≥ 18 (en la primera PC se instaló v26.13.0 LTS).
